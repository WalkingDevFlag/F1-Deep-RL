Reward Policy:
New reward policies & penalties:
- Positive rewards (encourage behaviour):
	1) Forward speed reward — keep your existing +k * speed (encourages forward motion).
	2) Clearance reward — reward proportional to mean sensor distance (staying away from walls).
	3) Heading stability reward — small reward for small change in heading between steps (discourages violent oscillation).
	4) Progress / checkpoint reward — sparse + small dense reward for getting closer to the next checkpoint or passing one (the true 	   task objective).
- Penalties (discourage bad behaviour):
	1) Collision penalty — large negative when car.damaged becomes true (already have −1.0; keep or increase).
	2) Time penalty — tiny negative each step (avoid dithering / spinning in place).
	3) Steering-change penalty — small penalty for changing discrete action frequently (encourages smooth control).
	4) Reverse / negative-speed penalty — penalize backwards motion if not needed.
	5) Off-track timeout / stuck penalty — if car doesn’t move sufficiently for N steps, apply penalty and reset.

Bugs:
web/levelEditor.js: setWallExtractionState calls this.showWallExtractionOverlay() (around the wall extraction toggle), but no such method exists anywhere in the editor mixins—invoking wall extraction currently explodes with a TypeError before any work is done.
web/car.js: the boundary clamp still uses the constructor defaults (this.width/this.height) instead of the scaled sprite dimensions from setCarImage; the center is forced at least 32 px/16 px from the edges even if the actual car is wider, making the car feel like it hits invisible walls and still allowing rendered geometry to stick out.
web/editor/persistence.js: setSavingState rewrites saveButton.textContent to “Saving…”/“Save”, stripping the SVG icon/label/tooltip elements permanently—after the first save the button loses all styling and accessibility structure.
web/index.html: there is a duplicated ui-dock__items block (the level-editor tool buttons) dropped inside the script section along with stray </nav></div> closers; the page renders invalid DOM and those dead buttons sit in the document tree.
server.py: upload_track checks file.content_length > 25 * 1024 * 1024, but FileStorage.content_length is often None. In that case the comparison throws and every upload returns 500. Guard with if file.content_length and file.content_length > ... or fall back to request.content_length instead.
server.py: create_track_folder always writes a canonical.png, even when the user uploads .jpg/.svg. The copied data keeps the original format but now has a .png extension, so browsers fail to render the track art (and the default loader breaks). Either convert to PNG or keep the correct extension in both metadata and filename.
trainingController.js: togglePause unpauses by forcing game.lapStartTime = performance.now() - this.pausedElapsedLapTime even when no lap timer was running. Pausing before the first lap (or after a reset) restarts with a fabricated lap start, corrupting lap timing and rewards. Only set lapStartTime when it was non-null going into the pause.
trainingController.js: updateStatsDisplay keeps using performance.now() - this.trainingStartTime while paused, so the “Time Elapsed” counter drifts instead of freezing. Reuse the cached pausedElapsedTrainingTime when isPaused is true to keep the UI consistent with the paused state.


Optimizations:
car.js: extractCarPolygon runs a full image scan on every load (nested loops + neighbor checks across every pixel) producing thousands of points; consider precomputing a simplified outline or using a marching-squares style contour to avoid heavy per-frame transforms and collision checks with oversized polygons.
car.js: assessDamage steps over every pixel on each polygon edge every frame; a coarse spatial grid or sampling reduction would cut the O(pixels) cost that currently scales with car perimeter and FPS.
checkpoints.js: resizing invokes Math.round and trigonometric conversions on every mousemove; tracking deltas in screen space and applying once on mouseup would eliminate the high-frequency trig/allocations.
assetLoader.js: loadAssets creates a Promise wrapper around async/await, and the two image onload handlers duplicate resolve logic; leveraging Promise.all on trackImg.decode()/carImg.decode() would simplify and avoid multiple resolve calls.
